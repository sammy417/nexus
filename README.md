# NEXUS

개인 자산 포트폴리오 관리 웹 앱 (Next.js App Router + TypeScript + Tailwind CSS). 주식(국내/해외)·채권·현금·연금(DC/IRP)·기타(사용자 정의 카테고리) 자산의 보유 현황을 관리하고 (매수/매도 거래 기록이 아닌, 현재 상태를 직접 입력·수정하는 방식), 배당 수령 기록과 자산 추이·수익률 분석을 제공합니다. PC(데스크톱) 브라우저에 최적화된 사이드바 레이아웃과 토스(Toss) 스타일의 미니멀한 다크/라이트 모드를 지원합니다.

## 로컬 실행

**요구사항: Node.js 22.13 이상** (SQLite 데이터 계층이 Node 내장 `node:sqlite` 모듈을 사용합니다. `node -v`로 확인하세요.)

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:3000 접속. 최초 실행 시 `data/nexus.db` (SQLite, git에 커밋되지 않음)가 자동 생성되고 데모 데이터로 시딩됩니다.

> Node 22.13 미만에서 실행하면 SQLite 대신 인메모리 데이터 계층으로 자동 폴백됩니다 — 앱은 동작하지만 **서버 재시작 시 데이터가 사라집니다** (서버 콘솔에 경고 출력). 영속 저장이 필요하면 Node를 업그레이드하세요.

## 데이터 모델 — 자산 타입 확장하기

모든 자산은 `src/lib/models/asset.ts`의 discriminated union `Asset = CashAsset | StockAsset | BondAsset | PensionAsset | CustomAsset`로 정의됩니다. 채권(BOND)과 연금(PENSION)은 실제로 이 절차대로 추가해 설계를 검증했으며, 새 타입 추가 절차는 다음과 같습니다:

**컴파일러가 강제하는 단계** (빠뜨리면 `tsc`가 알려줌):

1. `AssetType`에 새 타입 문자열 추가 (예: `"PENSION"`)
2. `BaseAsset`을 확장한 인터페이스 추가 후 `Asset`·`AssetInput` 유니온에 포함
3. `asset-types.ts`에 라벨·표시 순서 추가
4. `portfolio-service.ts`의 `getAssetMetrics`에 case 추가 (`assertNever` exhaustiveness)
5. `AllocationBreakdown.tsx`의 `CATEGORY_COLOR`에 색 추가 — 새 색은 dataviz 검증(라이트/다크 서페이스, 색각 이상 구분)을 통과시킬 것

**컴파일러가 못 잡는 단계** (안전하게 실패하지만 조용히 빠짐 — 직접 챙길 것):

6. `validate-asset-input.ts`에 런타임 검증 branch 추가 — 없으면 새 타입 생성 요청이 400으로 거부됨
7. `AssetFormModal.tsx`에 입력 폼 필드 추가 — 없으면 UI에서 새 타입을 선택할 수 없음
8. (선택) `seed-data.ts`에 데모 데이터 추가

**리포지토리·API 코드는 자산 타입이 늘어나도 구조를 바꿀 필요가 없습니다.** SQLite/목업 리포지토리 둘 다 타입별 필드를 `payload` JSON으로 저장하므로 새 컬럼이나 마이그레이션이 필요 없습니다 (BOND 추가 시에도 마이그레이션 0건이었음). 히스토리 스냅샷의 타입별 구성(`byType`)도 자동으로 새 타입을 포함합니다.

## 데이터 계층 — SQLite / Mock 교체

`src/lib/repositories/index.ts`의 `getAssetRepository()`가 유일한 진입점입니다. 기본값은 파일 기반 SQLite(Node 내장 `node:sqlite`, 네이티브 애드온 불필요)이며, 아래처럼 환경변수로 순수 인메모리 목업으로 바꿀 수 있습니다 (프로세스 재시작 시 초기화됨 — 테스트/데모용):

```bash
DATA_LAYER=mock npm run dev
```

나중에 실제 서버 DB(Postgres 등)로 옮길 때도 `AssetRepository` 인터페이스를 구현하는 새 클래스만 추가하면 되고, API 라우트나 컴포넌트는 그대로 둘 수 있습니다.

## 언어 전환 (한국어/English)

사이드바 하단의 **언어 아이콘(KO/EN)** 으로 한국어와 영어를 전환할 수 있습니다. 선택값은 `localStorage`에 저장되어 새로고침 후에도 유지됩니다. 구현은 **한국어 원문을 키로 쓰는 경량 i18n**(`src/lib/i18n/`)으로, `t("한국어")`가 한국어일 땐 그대로, 영어일 땐 사전(`translations.ts`)에서 번역을 찾고 **없으면 한국어로 자연스럽게 폴백**합니다(화면이 절대 깨지지 않음). 내비게이션·페이지 제목·카드·표·설정·폼·빈 상태·토스트 등 사용자에게 보이는 문구를 번역하며, 소유자 이름처럼 사용자가 직접 입력한 값과 종목명 같은 데이터는 그대로 둡니다.

## 다크/라이트 모드

**설정 → 화면 테마**에서 **시스템 / 라이트 / 다크** 3가지 중 선택할 수 있습니다. 눈이 편한 다크 모드를 명시적으로 고정하거나, &lsquo;시스템&rsquo;을 선택하면 기기의 다크 모드 설정을 실시간으로 따라갑니다(OS 설정이 바뀌면 즉시 반영). 사이드바 하단의 해/달 아이콘은 라이트↔다크 빠른 전환 단축 버튼입니다. 선택값은 `localStorage`에 저장되고, 하이드레이션 전 인라인 스크립트로 클래스를 미리 설정해 깜빡임이 없습니다. Tailwind `darkMode: "class"` 전략을 사용합니다.

## 화면 구성 (데스크톱)

- **좌측 사이드바**: 대시보드/포트폴리오/분석/**주식**/배당/설정 내비게이션, "자산 추가" 버튼, 하단에 **금액 숨기기(프라이버시)**·테마 전환·언어 전환·초기화 버튼
- **주식 집중 분석**: 보유 자산 중 **주식만** 모아 분석하는 전용 메뉴 (소유자 필터·통화 토글 연동) — ① **섹터 구성 도넛**(기술·금융·헬스케어·소비재·통신 등, 하이브리드 분류: 자산 폼에서 수동 지정하거나 티커로 Yahoo `quoteSummary`에서 자동 조회 → `stock-sector.ts` 정규화, 저장은 마이그레이션 불필요한 `sector?` 필드), ② **지역(국내/해외)·통화(₩/$) 노출** 막대, ③ **집중도 지표**(Top 5 비중·실질 종목 수·HHI 기반 분산 점수, 편중 경고), ④ **손익 기여**(수익/손실 기여 1위), ⑤ **종목별 표**(섹터 배지·비중·평가금액·손익·기여도, 행 클릭 시 수정), ⑥ **밸류에이션 비교 표**(PER·PBR·시가총액·배당수익률·52주 위치 — Yahoo `quoteSummary`에서 티커 배치 조회, `/api/stocks/valuations` + `useStockValuations` 훅, 1시간 캐시, 조회 실패 시 안전 폴백), ⑦ **리스크 분석**(최근 1년 일간 시세 기반 — 종목별 **연율화 변동성·1년 수익률·최대 낙폭·52주 위치** 표 + **일간 수익률 상관관계 히트맵**(공통일 정렬, 빨강=동조·파랑=역행). `/api/stocks/history` + `useStockHistory` 훅, 계산은 `stock-risk-service.ts`, 6시간 캐시). 종목별 표는 다른 리스트처럼 기본 Top 5 + **더보기**로 접힙니다. 계산은 `stock-analysis-service.ts`로 분리하고, 스켈레톤·빈 상태·i18n을 갖춥니다.
- **금액 숨기기(프라이버시 모드)**: 사이드바 하단의 눈 아이콘을 누르면 모든 화면의 금액이 `•••••`로 가려집니다 — 총자산·손익·테이블·도넛·차트 축·툴팁까지 전부 포함하되, 수익률(%)·비중·차트 곡선 모양은 그대로 남겨 화면 공유 시에도 흐름은 파악할 수 있습니다. 선택값은 `localStorage`에 저장되어 새로고침 후에도 유지됩니다 (자산 입력 폼의 금액은 가리지 않음).
- **스켈레톤 로딩**: 데이터를 불러오는 동안 각 페이지(대시보드/포트폴리오/분석/배당)는 실제 레이아웃과 같은 형태의 스켈레톤(은은한 pulse)을 표시합니다 — 제목은 즉시 렌더되고 카드·차트·테이블 자리는 회색 블록으로 채워, 콘텐츠가 로드될 때 레이아웃이 튀지 않고(no layout shift) 체감 로딩이 빨라집니다. 배당 예측·다가오는 배당 카드는 외부 조회 중 별도 스켈레톤을 보여줍니다.
- **빈 상태 & 온보딩**: 자산이 하나도 없는 첫 실행 시 대시보드는 ₩0 카드 대신 **환영 화면**(NEXUS 소개 + 기능 안내 카드 + "첫 자산 추가하기" CTA)을 보여줍니다. 포트폴리오·분석·배당도 비어 있을 때 안내 문구와 바로가기 버튼이 있는 빈 상태 카드를 표시하며, "자산 자체가 없음"과 "소유자 필터 결과가 없음"을 구분해 각각 다른 메시지(예: "OO 명의의 자산이 없어요 — 필터를 바꾸거나 자산을 추가해 보세요")를 안내합니다.
- **마이크로 인터랙션**: 주요 금액(총자산·투자원금·평가손익·분석 스탯 타일·배당 스탯/예상 배당)은 로드·값 변경 시 0(또는 이전 값)에서 목표값까지 **부드럽게 카운트업**(ease-out)합니다. 프라이버시 마스킹 중이거나 `prefers-reduced-motion`이 켜진 경우, 값이 그대로일 때는 애니메이션을 건너뜁니다. 페이지 이동 시에는 콘텐츠가 살짝 **페이드인**되어 전환이 매끄럽습니다.
- **대시보드**: 총 자산 요약 카드 + 자산 구성 도넛 차트(2:1 그리드, 세그먼트/범례 호버 시 중앙에 카테고리별 금액·비중 표시), 총 자산 추이 차트, 보유 자산 미리보기
- **포트폴리오**: **한국주식 / 해외주식 / 채권 / 현금 / 연금 / 기타** 카테고리별 섹션. 주식의 국내/해외 구분은 시장(KOSPI·KOSDAQ·KRX) → 티커 형식(6자리 숫자) → 통화 순으로 자동 판별하며 저장 스키마 변경 없이 파생됩니다. 각 섹션에 카테고리 합계, **비중 Top 5 가로 바 차트**, 그리고 카테고리 내 비중(%) 컬럼이 추가된 테이블이 표시됩니다 (행 클릭/연필로 수정, 휴지통으로 삭제, USD 자산 배지). 테이블 헤더(자산·투자 원금·평가 금액·비중·평가 손익)를 클릭하면 해당 컬럼 기준으로 내림/오름차순 정렬됩니다
- **분석**: 일별 스냅샷을 활용한 통계 페이지 — 전체/1개월/3개월 수익률과 최대 낙폭(MDD) 스탯 타일, 월별 수익률 막대 차트(월말 평가액의 전월 대비 변화), 카테고리별 평가 손익 다이버징 바, 전체 기간의 평가 금액 vs 투자 원금 라인 차트(크로스헤어 툴팁)
- **배당**: 배당·이자 수령 기록 관리 — "배당 추가" 다이얼로그(종목명 자동완성, ₩/$ 금액, **소유자**, 지급일, 메모)로 입력하고, 올해 누적·최근 12개월·월 평균·이번 달 스탯 타일과 최근 12개월 월별 배당 막대 차트, 월별 그룹 목록(소유자 배지·삭제 가능)으로 확인합니다. 배당에도 소유자 태그가 있어 상단의 **전체/본인/배우자/자녀/공동 필터**로 통계·차트·목록·예측이 모두 해당 소유자 기준으로 재계산됩니다. 자산과 별개의 이벤트 기록이라 매도한 종목의 과거 배당도 그대로 남습니다
- **배당 자동 분석 (입력 불필요)**: 보유 주식의 티커로 외부 배당 이력(`/api/dividends/forecast` → 야후 차트 API `events=div`, 1시간 캐시)을 조회해 자동 표시합니다 — ① **예상 연간 배당**: 최근 12개월 주당 배당 × 현재 보유 수량(세전 추정, 원화 환산), **세후 추정(원천징수 15.4% 가정)**, 포트폴리오 배당수익률, 종목별 주당 배당·예상 수령액·시가 배당률 테이블(예상 수령액 큰 순 Top 5 기본 표시, 6개 이상이면 **더보기**로 펼침). ② **다가오는 배당**: 과거 지급 주기를 추정해 다음 배당락 예상 시기(D-day)와 금액(가까운 순 Top 5 기본 표시, **더보기**로 나머지 펼침). ③ **받은 배당 기록 제안**: 외부 이력의 최근 지급 건 중 아직 기록하지 않은 것을 찾아 **원클릭으로 기록에 추가**(이미 기록된 건은 종목명+월 기준 자동 제외). 모두 추정임을 명시하고 조회 실패 종목은 표기됩니다
- **소유자 구분 (가족 공용 모드)**: 로그인 없이 자산마다 소유자 태그(**본인/배우자/자녀/공동**)를 붙여 분리 관리합니다. 자산 추가/수정 폼에서 소유자를 선택하고(기존 데이터는 미지정 시 공동 처리 — 마이그레이션 불필요), 대시보드/포트폴리오/분석 우측 상단의 **전체/본인/배우자/자녀/공동 필터**로 모든 화면(총자산·도넛·테이블·카테고리 손익·**총 자산 추이 및 분석 전체**)이 해당 소유자 기준으로 재계산됩니다. "전체"가 가족 합산 뷰이고, 포트폴리오 각 자산에는 소유자 배지가 표시됩니다. 필터 선택은 localStorage에 유지됩니다.
- **소유자 이름·색상 커스터마이즈 (설정)**: **설정 → 소유자 태그**에서 각 소유자의 표시 이름(예: 본인→"성민", 자녀→"하윤")과 **색상**을 바꿀 수 있습니다. 색은 컬러 피커로 자유롭게 고르며(행마다 실시간 미리보기 배지 + 기본색 되돌리기 버튼), **앱 전체**에 반영됩니다 — 자산·배당 배지, 소유자 도넛/범례, 성과 카드 점, **소유자 필터 칩의 색 점**, **자산·배당 추가 폼의 소유자 선택 점**, 합산 뷰의 소유자 이름, 그리고 특정 소유자로 필터링했을 때 **대시보드 총자산 추이선·분석 성장 그래프의 평가선 색**까지 모두 해당 소유자 색을 따릅니다(임의 색도 인라인 스타일로 동작). 기본색은 라이트·다크 모드 모두에서 잘 보이도록 검증된 4색 팔레트이고, 이름·색 모두 `settings` 테이블에 저장되어 백업에도 포함됩니다. 자녀 항목을 쓰지 않으면 이름은 비워두면 되고(기본 이름으로 표시), 자녀 태그로 자녀 명의 자산·배당도 별도 관리할 수 있습니다.
- **소유자별 히스토리 & 분석**: 일별 스냅샷에 소유자별 원금·평가금액(`byOwner`)을 함께 기록하므로, 소유자 필터를 켜면 총 자산 추이·기간 수익률·최대 낙폭·성장 차트가 그 사람 기준으로 표시됩니다(소유자별 기록이 없는 과거 구간은 현재 비중으로 추정하며 안내). 분석 페이지 "전체" 뷰에는 소유자별 평가금액·손익을 나란히 비교하는 **소유자별 성과** 카드가 추가됩니다.
- **소유자별 구성 도넛**: 대시보드에 소유자별 총자산 비중 도넛이 추가됩니다 — 소유자 필터와 무관하게 항상 전체(합산) 기준으로 "우리 집 자산에서 각자의 몫"을 보여줍니다.
- **같은 종목 합산 뷰**: 포트폴리오의 "같은 종목 합산" 토글을 켜면 같은 티커(+통화)의 주식이 한 줄로 병합됩니다 — 수량 합산, 평단가는 보유량 가중평균, 소유자 배지 복수 표시, 서브라인에 "N건 합산: 본인 30주 · 배우자 10주" 내역 표기. 합산 행은 읽기 전용이며(수정/삭제는 합산 해제 후), Top 비중 차트도 합산 기준으로 갱신됩니다. 토글 상태는 localStorage에 유지됩니다.
- **표시 통화 전환**: 대시보드/포트폴리오/분석 우측 상단의 ₩/$ 토글로 모든 금액(요약·도넛·추이 차트·테이블)을 원화 또는 달러로 표시. 달러 모드에서는 적용 환율($1 = ₩N)을 함께 표기하며, 선택은 localStorage에 저장됩니다. 환율 조회(`/api/fx`)에 실패하면 기본값(₩1,400)으로 폴백하고 그 사실을 표시합니다.

## 자산 추가 폼 — 필수/선택 항목과 현재가 자동 조회

자산 추가 시 필수 입력은 최소한으로 유지됩니다:

| 종류 | 필수 | 선택 |
|---|---|---|
| 주식 | 종목명, 보유 수량 | 티커, 시장, 평단가 |
| 채권 | 자산명, 매입 금액 | 현재 평가 금액(미입력 시 매입 금액), 표면금리, 만기일 |
| 현금 | 자산명, 금액 | - |
| 연금 | 자산명, 납입 원금 | 계좌 유형(DC·IRP·연금저축 등 자유 입력), 현재 평가 금액 |
| 기타 | 자산명, 매입 금액 | 카테고리(부동산·금·암호화폐 등 자유 입력), 현재 평가 금액 |

모든 자산은 **원화(₩)/달러($) 중 입력 통화를 선택**할 수 있습니다. 금액은 입력한 통화 그대로 저장되고, 평가/합산 시점에 실시간 USDKRW 환율(야후 파이낸스)로 원화 기준 환산됩니다 — 환율이 움직이면 달러 자산의 원화 평가액도 함께 움직입니다.

**주식 시세는 저장 시점 외에도 언제든 일괄 갱신할 수 있습니다**: 대시보드/포트폴리오 헤더의 "시세" 버튼을 누르면 보유 종목 전체의 현재가를 다시 조회해 반영하고(`POST /api/assets/refresh-prices`, 종목 통화 기준으로 저장), 갱신되면 오늘 스냅샷도 함께 기록됩니다. 앱에 처음 접속할 때 세션당 1회 자동으로도 갱신되며, 마지막 갱신 시각이 버튼 옆에 표시됩니다. 조회 실패 종목이 있어도 나머지는 정상 갱신됩니다.

**주식의 현재가는 입력받지 않고 저장 시 자동 조회합니다** (`/api/quote` → 야후 파이낸스 차트 API, API 키 불필요):

- 국내 6자리 코드는 KOSPI(`.KS`)/KOSDAQ(`.KQ`)으로, 알파벳 티커는 미국 시장으로 매핑됩니다.
- 미국 주식은 USDKRW 환율로 원화 환산해 저장합니다 (앱 전체가 KRW 기준).
- 조회 우선순위: 티커 조회 성공값 → 평단가 → (수정 시) 기존 저장값. 전부 없으면 안내 문구와 함께 저장이 중단됩니다. 평단가를 비우면 조회된 현재가로 채워집니다(손익 0에서 시작).
- 시세는 서버에서 5분간 캐시되며, 테스트/차단 환경에서는 `QUOTE_API_BASE` 환경변수로 엔드포인트를 교체할 수 있습니다.

## 자산 히스토리 & 추이 차트

일별 스냅샷(`snapshots` 테이블, 날짜당 1행)으로 총 자산 추이를 기록합니다:

- **기록 시점**: 자산을 추가/수정/삭제할 때마다, 그리고 대시보드 접속 시(하루 1회 갱신) 오늘 날짜의 스냅샷이 현재 자산 상태로 덮어써집니다.
- **데모 히스토리**: DB가 비어 있으면 최초 접속 시 현재 자산 가치를 기준으로 90일치 히스토리를 생성해 시딩합니다(고정 시드 난수 워크 — 데모용). 이후 실제 기록이 쌓이면서 대체됩니다.
- **차트**: 대시보드의 "총 자산 추이" 카드. 1개월/3개월/전체 기간 탭, 구간 손익 요약, 호버 시 크로스헤어 + 날짜별 평가금액/전일 대비 툴팁, "표로 보기"로 원본 수치 테이블 확인 가능. 외부 차트 라이브러리 없이 SVG로 구현되어 있습니다.

## 데이터 백업 (설정 페이지)

데이터는 로컬 `data/nexus.db`에만 저장되므로, **설정** 페이지에서 JSON 백업을 관리할 수 있습니다:

- **백업 내보내기**: 모든 자산·배당·자산 추이(스냅샷)와 설정(소유자 이름)을 `nexus-backup-YYYY-MM-DD.json` 파일 하나로 다운로드합니다. 클라우드 드라이브 등 안전한 곳에 보관하면 데이터가 초기화돼도 복원할 수 있습니다.
- **백업 가져오기**: 내보낸 JSON을 업로드해 복원합니다. 서버에서 형식·무결성을 검증(`app`/`version`/각 레코드)한 뒤, id·생성일·소유자 등 원본 필드를 **그대로 보존**해 되살리며, 백업에 포함된 소유자 이름 설정도 함께 복원합니다(설정이 없는 구버전 백업은 기본 이름 유지).
- 가져오기는 **현재 데이터를 전부 대체**(병합 아님)하므로 확인 창을 거치며, 복원 후 화면이 자동 새로고침됩니다.

> 이 방식은 파일 기반 수동 백업입니다. 컨테이너 재시작 등으로 데이터가 초기화될 수 있는 환경에서는 정기적으로 내보내 두거나, 근본적으로는 외부 영속 DB(Turso 등)로 전환하는 것을 권장합니다.

### 반복 테스트를 위한 초기화

자산 데이터는 SQLite 파일(`data/nexus.db`)에 저장되어 서버를 재시작해도 유지됩니다. 시나리오를 처음부터 다시 테스트하고 싶다면 사이드바 하단의 초기화(↺) 아이콘을 눌러 데모 데이터로 되돌릴 수 있습니다 (`data/nexus.db` 파일을 직접 삭제해도 다음 요청 시 재시딩됩니다).

### 확인해볼 시나리오 예시

1. 사이드바 "자산 추가" → 자산 종류(주식/현금) 선택 후 신규 자산 등록 → 대시보드/포트폴리오에 반영되는지 확인
2. 포트폴리오 테이블에서 자산 행 클릭(또는 행 우측 연필 버튼) → 수정 다이얼로그에서 보유 수량 등 값을 바꿔 저장 → 원금/평가금액/손익이 재계산되어 반영되는지 확인 (예: 30주 → 5주 감소, 5주 → 20주 증가)
3. 포트폴리오 테이블 각 행 우측의 휴지통 버튼(또는 수정 다이얼로그 하단의 삭제 버튼)으로 자산 삭제 → 확인 창 후 목록과 대시보드 총 자산에서 제거되는지 확인
4. 대시보드의 "자산 구성" 비중 그래프가 종류별로 갱신되는지 확인
5. 포트폴리오 페이지에서 주식/현금이 섹션별로 그룹핑되어 보이는지 확인
6. 새로고침(F5) 또는 서버 재시작 후에도 위 변경 사항이 유지되는지 확인
7. 사이드바 하단 아이콘으로 다크/라이트 모드 전환, ↺ 버튼으로 초기 상태로 재설정
